    Check your grouping on real feedback

    1. Sample answers to one survey question across the range of lengths people write. Code the themes by hand using a shared set of labels.
    2. Pick short and long versions of comments that still raise the same issue. Compare both versions with the same set of candidates and see whether the closest match changes theme.
    3. Run your usual grouping workflow. Of the pairs it puts together, what share have a theme in common? Of the pairs with a theme in common, what share land in the same group?
    4. Make both comparisons separately for short pairs, long pairs and mixed-length pairs. If the model struggles at some lengths, use the same checks to compare another embedding model.
    How this demo was made

    Liu tested average cosine on shorter and longer excerpts from the same comments. He also ran a placebo that swapped in comments of similar length, and adjusted the average by computing it within word-count bands and weighting the bands equally. This demo adapts his excerpt check to nearest matches.

    The reference and candidates come from a set of 48 fictional comments with manually assigned themes. The demo starts with the short versions and swaps one of the 47 candidates for its expanded version. It ranks every candidate by its cosine similarity to the reference using precomputed BGE embeddings.

    The expansion adds detail as well as words. The example shows how a change in wording can reorder nearest matches.

    Based on Fengming Liu’s preprint on embedding cosine and text length. Source code and data script on GitHub.
